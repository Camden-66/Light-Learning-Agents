# Light Learning Agents

Can an agent **learn a hidden light schedule organically**, the way a person
would: look a few times, update a mental model of when the lamp is on, then
guess the peak? That is the question. This repo is a small, reproducible
benchmark for it.

## What the environment is

`RoomEnv` is **not** a physics engine. There are no walls, bulbs, or photons.
It is a **generative world**: a hidden peak plus a stochastic light, wrapped
in a sequential experiment so agents can act without seeing the mechanism.

Each episode:

1. A hidden peak θ is drawn uniformly from `{4, …, 27}` among 32 time slots
   `t ∈ {0, …, 31}`.
2. The agent may inspect a slot at most `B ∈ {4, 8, 16, 32}` times. Repeats
   count. Each look returns only **on** or **off**.
3. The light is generated by a fixed Bernoulli bump (the **ground-truth
   generator**, private to the environment):

```text
P(on | t, θ) = 0.05 + 0.90 · exp(-(t − θ)² / 18)
```

4. After the budget is spent, the agent names θ̂. Score is `|θ − θ̂|` (lower
   is better). Terminal reward is `-|θ − θ̂| / 31`.

What the agent is allowed to see: its own on/off history and remaining looks.
What it must not see until it commits: θ, the score, and the formula above.
Outcomes are deterministic given `(episode_seed, slot, repeat)`, so two agents
that query the same slot in the same episode get the same bit.

`GymRoomEnv` is the same world as a Gymnasium `Discrete(32)` task with a
length-66 public observation (on-counts, visit-counts, remaining budget,
commit flag).

## What the two baselines do

They answer two different questions. Do not report them as matched.

### Oracle MLE (`PassiveUniformOracleMLE`)

This baseline **is given the true formula**. It does not search for a
generative model. It spends the budget on i.i.d. uniform slots, then picks the
θ in `{4, …, 27}` that maximizes the canonical Bernoulli likelihood (smallest
θ on a tie).

Call it **passive uniform-query oracle-likelihood MLE**. It is an
information-privileged reference: “if you already know how the lamp works, how
well can you locate the peak?” It is **not** an organic learner.

### RL (`PPORoomAgent` / explainer REINFORCE)

This baseline **is not given the formula**. It only sees the public Gym vector
and the terminal reward. Looks give reward 0. It learns a **look / guess
policy** across many training episodes.

Official PPO: Stable-Baselines3, four budgets, five training seeds, held-out
eval owned by the evaluator (`light_learning.ppo`). The webpage trainer is a
small **REINFORCE** demo on the same Gym contract; its numbers are smoke
samples, not the PPO table.

RL can get good at the task without ever representing `P(on | t)`. That is
the contrast the thesis needs.

## What the emergent model is building

`EmergentBumpAgent` is a **world model of the lamp**, not a policy and not a
copy of `RoomEnv`.

The environment already **is** the true generator. The agent is forbidden to
read that generator. It is only allowed the same on/off bits a human would
get. Internally it assumes something weaker and qualitative: “the light is
probably a bump in time,”

```text
p(on | t) ≈ a + b · exp(-(t − μ)² / (2σ²))
```

and infers `(μ, σ, a, b)` from those bits. The canonical constants
`(0.05, 0.90, 18)` are never passed in. In English: it is reconstructing
**where the peak is, how wide the bump is, how bright the peak is, and how
often the lamp flickers when you are far from the peak.**

The true room bump is a Gaussian with `σ = 3` (because `exp(-d²/18)` equals
`exp(-d² / (2σ²))` at `σ = 3`). If posterior mass piles up near `σ ≈ 3` and
the implied curve tracks the hidden `P(on | t, θ)`, the agent recovered the
**structure of the world**, not just a lucky θ̂.

Optional pooling: after a guess, training rooms may reveal θ. The agent
updates a prior over **shape only** `(σ, a, b)` — “how this kind of lamp
behaves” — then on a new room infers a new peak. That is the organic
cross-episode step. RL typically updates “where to click next”; this model
updates “how the light is generated.”

```bash
uv run light-learning compare --budget 4 --budget 8
```

`oracle_mle` = open-book peak location. `basic_rl_reinforce` = policy
learning. `emergent_*` = closed-book world model. This comparison is **not**

Python 3.12 and `uv`:

```bash

```

```python
from light_learning.evaluator import run_evaluation
from light_learning.mle import PassiveUniformOracleMLE

records = run_evaluation(
    lambda *, policy_seed: PassiveUniformOracleMLE(query_seed=policy_seed),
    output_dir="evaluation-runs",
    run_id="mle-pilot",
    profile="pilot",            # 10 episodes/cell; "full" is 100
    agent_id="passive-uniform-oracle-likelihood-mle",
    agent_version="0.2.0",
    condition="oracle_mle",
)
```

A factory that accepts `policy_seed` gets an evaluator-owned seed independent
of hidden θ. PPO: `train_ppo_suite(...)` then `PPORoomAgent`. Never train on
held-out IDs or seeds (`assert_training_separation`).

Local LLM: `uv run light-learning preflight` (no auto-pull). Hand
`LLMRoomAgent` to `run_evaluation`. Qualitative prompts measure in-context
discovery; disclosed-likelihood is an ablation. Label information regimes
faithfully.
The run directory holds `records.jsonl` (flushed per episode), `summary.json`,
and `manifest.json`. Re-running the same `run_id` resumes and skips completed
episodes; a mismatched manifest or duplicate records are rejected.

uv run light-learning validate-profiles

## Setup

This project targets Python 3.12 and `uv`:

```bash
uv sync --extra dev --extra rl
uv run pytest
```

The `rl` extra is separately declared so non-RL users can omit it; include it
whenever you train PPO or run the complete test suite.

`light_learning.ppo.train_ppo_suite(...)` defaults to the required four budgets
and five independent training seeds, saves one checkpoint per run, and writes a
manifest. The evaluator loads each checkpoint through `PPORoomAgent` and owns
held-out episodes, `EpisodeRecord` construction, and all reported metrics. Use
`assert_training_separation` to prove RL training IDs and seeds never overlap
the held-out banks.

The MLE agent requires an explicit evaluator-owned `query_seed` for each
episode, supplied by the `policy_seed` factory contract above. It must be
independent of the hidden room seed; this makes its uniform query schedule
reproducible across retries and resumed runs.

The local LLM experiment needs a running Ollama server and both requested
models installed. The CLI never pulls models automatically. Check readiness
first:

```bash
uv run light-learning preflight
```

After freeing sufficient disk space and installing a model yourself, hand the
constructed `LLMRoomAgent` to `run_evaluation` as shown above. The evaluator
owns pilot/full execution and run-directory output.

## Experiment interpretation

The primary LLM prompt gives only qualitative room rules, so it measures
zero-shot in-context model discovery rather than online weight learning. The
disclosed-likelihood condition is an ablation over exactly one variable: both
arms state the answer range, and only the disclosed arm supplies the Bernoulli
likelihood.

The oracle MLE and trained RL baselines have different information regimes;
report their labels faithfully. In particular the three are not a ladder. Oracle
MLE has the exact likelihood but zero task exposure and a deliberately
non-adaptive uniform query schedule; PPO has large task exposure and an adaptive
policy but no analytic knowledge of the likelihood. Oracle MLE is therefore not
a performance ceiling: an adaptive querier using the same exact likelihood
reaches MAE 2.54/1.23/0.55/0.30 at budgets 4/8/16/32 against passive uniform
MLE's 3.62/2.33/1.24/0.59, so roughly a third to a half of the oracle MLE's
error is query strategy rather than model knowledge.
